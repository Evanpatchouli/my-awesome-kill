## 接力规则

每个可验证单元结束后更新本文件并采样，大检索、长日志、新重单元开始前也采样。读取当前进程 CODEX_THREAD_ID，在 CODEX_HOME/sessions 或 %USERPROFILE%/.codex/sessions 只匹配完整 ID 的 rollout-*.jsonl。仅提取最近一条有效 payload.type=token_count 的 timestamp、info.last_token_usage.total_tokens 与正数 info.model_context_window。以两者相除计算比例，禁止用跨次累计或按最新文件猜测。无可靠样本时记录事实，按所需空间提前交接。自动压缩后先从现场和采样核实已完成操作。初查采样 31573/828400（3.81%）。

“你是当前主会话。请持续推进 P1，在自己的上下文达到 80% 或下一单元可能挤占交接空间时，按相同协议自行创建一个直接后继，并将同样的授权和停止条件继续传递。交接成功后立即结束；P1 验收完成后结束接力。”

达到阈值不领新实现。先收口所有写入者，在本文件与 .agents/handoff.md 保存项目分支、用户改动、完成边界、证据、决定、验证结果/复现、剩余项、一个明确第一步、交接原因与新鲜采样（时间、用量、容量、占比）。用 list_projects 核对，再以 create_thread 发起全新本地会话，首条消息包含目标、独立实现边界、两份状态文件、实际进度、第一步、上述授权和下节全文。受理后立即结束，禁止监测后继。创建不明先核实以防重复；工具不可用留完整交接并给用户可手动发送的 prompt。只由用户可解决的阻塞直接报告。完成验收报告内容、启动、验证、review、限制并结束接力。

## 每一任必须原样传递的项目绑定规则

本次 P1 接力固定属于 Codex 桌面端已登记的本地项目：
- 项目名：my-awesome-kill
- 本地路径：E:\my-awesome-kill
- hostId：local
- projectId：56a3f74c-1f60-47c5-8e25-30ee6f6375cb

每一任创建后继会话时，都必须遵守以下规则。本节优先于前文中“同一项目”“当前项目”等简写。

1. 创建前调用 list_projects，确认上述 projectId 在 local 主机上仍对应 E:\my-awesome-kill。仅凭会话标题、当前 shell 路径或侧栏选中项，不能判定新会话的项目归属。
2. 调用 create_thread 时，显式传入以下 target 对象：
   {"type":"project","projectId":"56a3f74c-1f60-47c5-8e25-30ee6f6375cb","environment":{"type":"local"}}
3. 如果项目记录缺失、ID 与路径不匹配，或工具无法接受这个 target，就停在创建之前，保留交接文档并向用户报告具体情况。禁止回退到默认项目、projectless、其他项目或新 worktree。
4. 把本节全文原样放入每一个后继会话的首条 prompt，包括这一条传递规则。首任也将本节保存到 `.agents/current-task.md`，供后续核对。不能只写“继续在同一项目接力”。
5. 每一任接棒时，先核对自己的会话项目归属和工作目录。若发现归属错误，停止写入和传棒，报告实际归属。确认无误后再继续 P1。
